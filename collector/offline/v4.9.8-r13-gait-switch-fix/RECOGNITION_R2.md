# v4.9.8-r2：多人标注、参数与判别依据

## 用其他视频

在本目录安装 `requirements.txt`（你的环境已有依赖时跳过），然后：

```powershell
python recognize_actions.py --multi-person "D:\videos\new.mp4" --output "D:\labeled" --device auto
```

每个输入视频独立追踪、建立衣着档案和编号。支持同一命令输入文件列表或目录。默认生成 `review.mp4` 和 CSV；`--no-preview` 只出表。`--resume` 仅复用经签名核对的缓存或成品。旋转元数据错误时按实际需要加 `--rotate 90`（或 180 / 270）。当前视频没有人工写死 ID、人数或动作时间。

## 参数对应关系

| 设置 | 默认 / 本次 | 用途 |
|---|---|---|
| `--imgsz` / `--box-conf` | `960` / `0.10` | 逐帧人体姿态检测；权重 `models/yolo26s-pose.pt`，跟踪配置 `bytetrack_actions.yaml`。 |
| `--min-track-s` / `--max-track-gap-s` | `0.60 s` / `0.35 s` | 排除过短的轨迹；长断观测不拼成连续动作。 |
| `--reconnect-gap-s` | `2 s` | 原有短时断轨接回，结合时空位置与外观。 |
| `--reentry-gap-s` | `60 s` | 同一视频的外观回连；`0` 关闭。 |
| `--action-config` | `action_config.json` | 多人动作规则参数；`final_parameters.json` 保留原包的旧版单人深蹲参数，不是多人入口默认。 |
| `--ignore-static-roi` | 默认关闭；示例见下 | 只对已知固定机位启用。不是通用镜面分类器。 |

## 判别如何分层

1. **人的重入与 ID。** ByteTrack 先形成原始轨迹；短时接回后，用肩、髋、膝定位上衣和裤子，从清晰的多帧取亮度、饱和度和色彩特征。长间隔回连要求候选不能同时存在，衣着匹配且没有相近的竞争轨迹。r1/r2 内部归一化总距离上限 `0.080`、裤装差异上限 `0.13`、竞争差异带 `0.026`，仅对本算法的特征量表有效。过滤和动作分析之后，只给有效人物安排 `1, 2, 3…`；同帧首次出现以框中心从左到右排序。重入回连的片段沿用原显示 ID，不补写离画时的动作。
2. **动作。** 主流程区分站立、走路、跑步、深蹲、上楼和下楼；不足以判别时用候选或其他。短跑步补判需要连续左右脚交替、同步躯干起伏和可见位移；至少 4 个相配的交替事件，步间隔和节律必须一致。步频、速度和摆臂都不能单独定为跑步。像素关键点不等于真实触地。其余步态、深蹲和楼梯的基础规则见 `ACTION_RULES.md`。r2 只改人物显示编号，沿用 r1 的判别。
3. **镜像。** 区域坐标是显示画面的 `x1,y1,x2,y2`，都在 `[0,1]`，可重复指定。只有全轨迹框落在该区域且近乎静止才排除。换视频、换机位时不要沿用不适用的区域。本次复现：

```powershell
python recognize_actions.py --multi-person "飞书20261120-161019.mp4" --output "out_161019" --device auto --ignore-static-roi 0.09,0.20,0.19,0.62
```

`track_id_map.csv` 中 `track_id` 是正式显示号；空值是被过滤或证据不足。`yolo_track_id` / `internal_track_id` 仅用于诊断；`track_links.csv` 用原始编号，`reentry_links.csv` 用短断轨接回后的内部编号。换装、同装、长时间离画或密集遮挡时，不保证能识别为同一人。
