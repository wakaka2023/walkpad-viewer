# v4.9.8 性能验证

此版沿用 v4.9.7 的模型权重、YOLO 输入尺寸（默认 960）、逐帧推理、ByteTrack 配置、动作规则、阈值、每人独立跟踪和深蹲计次。编码仍使用 libx264、CRF 21、veryfast，原音频包直接复制。近景光流的角点与追踪按帧对并行计算，地面配准和证据仍按原顺序处理。短轨重连只计算候选边真正使用的外观样本。数值滑窗按有效样本数分组计算。预览复用 RGB 缓冲区和文字尺寸，成片校验在一次读取中核对帧和所有音轨。

| 计算方式 | 原视频 | v4.9.7 | v4.9.8 | 节省时间 |
|---|---|---:|---:|---:|
| 首次完整运行（含 YOLO、光流、渲染和校验） | 飞书20261120-100136，379 帧 | 17.54 秒 | 10.53 秒 | 40% |
| 跟踪、镜头运动缓存就绪；重新分析和渲染 | 飞书20261119-134801，2558 帧 | 114.73 秒 | 76.72 秒 | 33% |
| 同样的输入、参数和输出目录，校验并复用成品 | 上述两段 | — | 0.78 / 0.91 秒 | — |

在同一台 RTX PRO 5000 Blackwell 服务器、同一 Python 环境、同一 GPU（CUDA_VISIBLE_DEVICES=0）上测量。OpenCV、OMP、OpenBLAS 内部线程设为 1（`OPENCV_FOR_THREADS_NUM=1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1`），近景光流最多同时处理 4 个相邻帧对。时间使用同一测速脚本从导入模块到完成输出，含 I/O 和校验，是该环境的单次测量，其他机器、视频分辨率、负载下会有区别。首次完整运行与兼容中间缓存运行分开计时；长视频的首次无缓存时间没有测量。旧版升级到此版时，镜头运动缓存会重建一次，长视频旧缓存升级的耗时不能用表中第二行估算。

- 近景样本光流 7.16 → 1.58 秒，成片渲染 4.01 → 2.61 秒，YOLO 跟踪 3.72 → 3.75 秒。
- 134801 短轨重连 14.12 → 7.22 秒，分析 1.85 → 1.13 秒，成片渲染 92.01 → 61.76 秒。输出预览仍约占此次运行的八成。只需要标签与边界时可指定 `--no-preview`，避免预览编码和校验。
- 同输入再次运行需要用原输出目录及 `--resume`。默认 ByteTrack 下会先核对输入、配置和成品的 SHA-256；只匹配时复用现有成片和表格。`--resume --recompute-results` 可跳过成品复用，保留兼容的中间缓存。输出中的 `completed_signature.json` 和 `TIMING` 分别记录复用所需信息和实际阶段耗时。

两段服务器对照的全部 CSV、预览校验 JSON、参数 JSON 和成片 MP4 均逐字节一致；帧时间戳的最大误差均为 0 秒。另对五段开发样本（共 8,036 帧、13,801 行逐人逐帧记录）做了同数据重放，涉及动作、候选、阶段、边界和证据的全部分析 CSV 保持一致。240 组包含不规则时间戳、缺失数据和不同窗口大小的滑窗对照位级一致。这些验证的是速度优化没有改变已有样本的输出，不能当作新场景的独立准确率。
