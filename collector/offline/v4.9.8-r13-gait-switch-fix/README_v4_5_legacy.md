# 深蹲标注 v4.5：正侧面综合评分与双画面同步标注

日期：2026-11-18。基于用户提供的 v4.4 包修订。权重、原始检测参数、各项评分阈值保持原值；新增可移植双视角入口、时间配对、可观测项目融合和双画面标注。旧版本说明与验证记录在 `*_v4_4_legacy.*`、`legacy_v4_4_validation/` 中，仅代表旧版。

## 最常用命令

在本 README 所在目录，使用已安装 `requirements.txt` 依赖的 Python 环境。

左边正面、右边侧面（如本次数据集）：

```powershell
python annotate_videos.py "C:\data\P48SQ2.mp4" --output "results_v4_5" --layout front-side --device 0
```

左边侧面、右边正面：

```powershell
python annotate_videos.py "C:\data\video.mp4" --output "results_v4_5" --layout side-front --device 0
```

视频左右分界不是正中时，增加 `--split-ratio 0.45`，表示左侧画面占原视频显示宽度的 45%。`--device cpu` 可使用 CPU；`--no-preview` 跳过编码，只输出区间、逐帧标签和评分。

同一目录混有单视角、双视角视频时，填写 `layout_map.example.json`，将示例文件名改为实际文件名，然后：

```powershell
python annotate_videos.py "C:\data\videos" --recursive --output "results_v4_5" --layout-map "my_layouts.json" --device 0
```

未在映射表中指定的视频使用 `--layout` 的默认值 `single`。单视角入口和原单视角规则保持 v4.4 行为：`--view front` 或 `--view side` 可明确视角。v4.5 本次更改的综合评分规则适用于双视角分支，不改变旧版联合 IMU 入口。

## 使用前提

双画面必须是**同一个人、同一组动作、时间同步的正面和侧面**。不要把两个不同的人、不同轮次或未同步的画面融合。程序不通过视频宽高或“出现两个人”猜测是否双视角，需要用 `--layout` 或映射表明确声明。不同步时应先同步视频；本版不会调整传感器时间轴。

当前版本支持同一个视频内左右并排的画面。上下布局、画中画、两个独立文件需先在视频侧整理为已同步的左右布局。主体应尽量拍全，至少一侧肩、髋、膝、踝持续清楚；正面双侧项目还要求双腿可见。

## 最终输出

每个视频输出目录根部是综合结果：

| 文件 | 内容 |
|---|---|
| `review.mp4` | 完整视频，两幅画面都显示同一个 OVERALL 综合评分、动作编号和 DOWN/UP 阶段，并各自绘制骨架 |
| `review.html` | 点击动作行播放该次深蹲，查看综合与分视角证据 |
| `repetitions.csv`、`events.json` | 每次动作综合评分、起止/最低点、观测项数、原因、分视角原始时间及边界来源 |
| `intervals.csv` | 同一套综合区间，时间采用 `[开始,结束)` |
| `frame_labels.csv` | 对每个原始视频帧连续写入所属动作、阶段及综合评分，不只标首尾 |
| `front/`、`side/` | 各自的姿态缓存、原始候选、分项指标；根部综合结果为最终输出 |
| `fusion_diagnostics.json` | 无观测项或视频边缘截断候选等记录 |
| `multiview_audit.json` | 帧数、时间轴、匹配次数、分级统计和输入哈希 |
| `layout_used.json`、`multiview_config_used.json` | 实际布局与融合参数 |

视频中第一行 `OVERALL` 是最终标签；第二行 `FRONT/SIDE evidence` 是各视角提供的证据，不能当成两个最终标签。共同指标去重后最多 8 项，单个视角最多提供 6 项。未观测项目不算通过，也不单独扣分。

视频保留源显示分辨率、逐帧 PTS 时间轴和帧数；重新编码效果副本，不包含音频。新双视角流程只读取视频，**不读取、不重采样、不修改传感器 CSV**。

## 评分与匹配规则

详见 `SCORING_RULES.md`。正面负责膝轨迹、躯干侧偏；侧面负责髋膝深度投影、髋肩上升协调。回位、踝点运动、躯干腿协调及间接协调线索只在可靠可观测时参与；同一项只计一次。

融合不会平均两幅画面的 GOOD/MID/POOR。某视角看不到另一视角能看到的问题，不能用一个 PASS 抵消可靠的 WARN/FAIL。可观测项中有严重问题则为差，只有轻度问题则为中，已观测项全部通过则为好。多个轻度问题不累加成差；间接线索最高为中。没有任何可靠观测项的候选不评分，记录原因，不输出“好”或“待复核”。

## 速度与缓存

只提取每侧姿态一次。需要改融合或评分参数后重跑时，使用同一输出目录并增加 `--resume`：

```powershell
python annotate_videos.py "C:\data\P48SQ2.mp4" --output "results_v4_5" --layout front-side --device 0 --resume
```

只有源视频、模型、裁剪区域和推理设置一致时才复用缓存；否则重新推理。`--resume` 不跳过重新检测、重新评分和导出。建议先用 `--no-preview` 调参，再生成视频。

## 验证范围

本版评分/集成测试 125 项，区间测试 55 项，共 180 项通过。其中新增双视角测试 23 项，覆盖漏检不串号、可靠异常不被另一视角抵消、缺失项目、间接线索上限、错配拒绝、视频边缘截断和两幅画面一致标注。

使用原始 P48SQ2 前 8.1 秒真实视频，在 GPU 上完整运行姿态推理、分侧检测、评分、融合和编码；3 次完整动作全部一一配对，示例 243 帧，导出 PTS 最大误差 0 秒。末尾被截断的一次起身没有当成“回位失败”评分。示例位于 `validation/real_gpu_smoke/`。

这是功能与回归验证，**没有独立专家标签准确率**。深度、协调等仍为二维视频的工程筛查代理量，不能当作已验证的三维解剖学质量结论。本次没有为了改变某个视频的评分而调低原阈值。
