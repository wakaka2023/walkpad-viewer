# Walkpad 鞋垫数据查看器

在浏览器里离线查看鞋垫压力与 IMU 录制的波形，并给出活动识别和走跑步态统计。所有解析与计算都在本机完成，不上传任何数据。

## 直接使用

克隆或下载本仓库后，双击 `index.html` 即可，不需要安装 Node.js，也不需要起服务器。页面以 `file://` 打开，调用的是仓库里预构建好的 `dist/app.js`。

支持拖入或选择的文件：

- 测量包导出的 `.zip`
- `.parquet` 导出
- 维特上位机（WT901 / JY901 等）导出的 `.txt` / `.csv`

测量包里带现场视频（`videos/*.mp4`）时，右下角浮出播放器。导出端写入了落地对时的包（`manifest.videos[]` 带首帧会话时刻）直接采用该起点，视频与设备刻度同一会话轴，起点可为负——摄像头常比设备先开录；此时不再需要校准。已核验的包打开即应用已知起点；其他双踝包点「自动校准」，比对视频小腿转动和双踝角速度，不用跳跃或先预测。公司采集网内直接打开本地 `index.html` 即可使用工作站 GPU，无需配置、令牌或本地模型。适用于 5–120 秒且双侧膝踝清楚可见的单段视频；不可达或匹配不唯一时保留原值，也可手填起点或用本地「首次蹲底对时」。IMU 和深蹲专项的游标随视频更新。

动作校准使用 Google MediaPipe Tasks Vision 与 Pose Landmarker Lite（[Apache 2.0](vendor/mediapipe-license.txt)，[模型来源](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)），顺序解码使用 [Mediabunny 1.66.2 源码](https://github.com/Vanilagy/mediabunny/tree/v1.66.2)（[MPL 2.0](vendor/mediabunny-license.txt)）。视频播放、手动对时和深蹲预测在本地运行。仅点「自动校准」时，首段视频和对时所需的双踝数据会加密发给公司采集网内的工作站；工作站不保存数据或结果。

同一测量包可同时包含左右鞋垫与左右脚踝 IMU：压力页显示鞋垫，IMU 页分开显示四路，深蹲专项用明确标为左踝、右踝的 Walkpad IMU 预测阶段，另用压力鞋垫计算各脚的压力指标。

深蹲专项预测后，四状态时间轴下方显示双踝的前后倾、左右倾和绕竖直相对转角。曲线按每次下降起点归零，与时间窗、视频游标同步；悬停读数，点击定位视频。逐次三向角表仍可核对蹲底值和站姿累计航向。

### 深蹲鞋垫相对压力

导入带 D56（每脚 56 通道、左右镜像布局）的测量 ZIP 后，打开「深蹲专项」即可看到 COP、单点峰值、单脚总信号和有效时段内的左右信号占比。压力、双踝角度、动作阶段和视频共用时间轴；悬停读数，点击曲线定位视频，不必先做深蹲预测。

- **相对单点峰值 / 单脚总信号**：以各点等面积计算，每帧取一脚 56 点非负 ADC 的最高值和总和。各指标分别用整份记录中双脚的最高单点读数、最高单脚总和作为 100%。两脚、各次深蹲和缩放窗口共用参照，百分比不用于不同记录间的绝对比较。
- **相对 COP**：按非负 ADC 加权，使用 `d56-v3-coordinates-20261023.json` 的 P1–P56 测点图面坐标；鞋垫轮廓和轨迹沿用同一套 D56 v3 图纸坐标，不是毫米坐标或整体 COP。预测后只画当前次的轨迹（下降起点至游标），两次动作之间只显示亮点；未分段时显示最近最多 1 秒。不跨缺测连线，信号为零不画 COP。
- **逐次汇总**：预测后按每次下降开始至上升结束统计，峰值只取该次原始有效帧，单脚总信号另列按有效时长计算的平均值。点击次数可定位到该次。
- **左右信号占比**：使用同一采集时段、按包内会话时钟对齐的双方有效帧。逐次占比为一侧总信号的时间积分除以左右两侧积分之和，并显示配对覆盖率；没有有效配对或总信号为零时留空。零点与灵敏度差异会影响结果，该占比不等于实际承重比例；无需导入压力标定。

### 其他显示项

IMU 页的六轴下面还可以叠两条窄带：温度，以及设备自报的俯仰角 / 侧倾角（`pitchDeg` / `sideTiltDeg`）。两条各按自己的 min–max 定量程，工具条「显示」里可以单独关掉；文件没有相应列（或整段为空）时不会多出空带。

文件格式、各页算法口径与已知边界集中在右上角「说明」抽屉里，按当前页签自动定位；低频控件收在工具条的「更多」里。

## 从源码构建

改代码才需要这一步，需要 Node.js 20 以上。

```bash
npm install
npm run build      # 产物写到 dist/app.js，页面直接加载它
npm run dev        # 开发时用 vite 起热更新服务
npm run typecheck  # 类型检查
```

`dist/app.js` 是单个 IIFE bundle，不压缩，便于现场排查；页面用经典脚本加载它，因此 `file://` 下也能跑。

## 页面

| 文件 | 用途 |
| --- | --- |
| `index.html` | 主查看器：压力波形、IMU、丢包与时间轴、活动分段、走跑步态报告 |
| `axis.html` | IMU 轴向推断：安装方向与重力参考的独立页 |
| `imu.html` | 维特 IMU 波形查看器：单设备六轴录制的独立工具 |

## 模型权重

权重以 JSON 形式放在 `src/`，构建时内联进 bundle，运行时不联网、不额外下载。

| 文件 | 用途 |
| --- | --- |
| `src/b1q-model.json` | 四类活动识别（静止 / 步行 / 跑步 / 其他）的默认模型 |
| `src/b1-model.json` | 同族早期版本，测试对照用 |
| `src/o1-model.json` | 早期候选模型，测试对拍用 |
| `src/moticon-tas-model.json` | 多域时序活动模型，页面上可切换试用，非默认 |
| `src/frozen_model.json` | GaitWindow 边界细化模型，页面可切换对照 |

`src/activity.ts` 加载默认的 B1Q；另外两个活动模型由页面开关决定是否启用。

## 目录

```
src/         TypeScript 源码（解析、波形、活动识别、IC/TO 与步态指标）
src/gait/    走跑步态：事件配对、设备俯仰、三轴加速度合量峰值、报告汇总
src/icto/    IC / TO 检测与校核
css/         样式
dist/        预构建产物，页面直接加载
tests/       单元测试与真实权重对拍
vendor/      parquet 解码器
```

## 测试

```bash
npm run typecheck
npm test                      # 交互与合成 IMU
node tests/gait.mjs           # 走跑指标与边界用例
node tests/activity.mjs       # 活动识别：解码、缺口、权重对拍
node tests/b1.mjs             # B1Q 权重对拍（b1.mjs b1q 为同名脚本）
```

真实录制固件（`tests/.activity-fixtures/`）不入库，涉及它的用例会自动 SKIP，其余用例可在空环境下直接跑。

## 指标口径

- **步频**＝计入的步数 ÷ 双脚共同可计步时长，不是整段时长；缺口部分不计入。
- **接地时间**＝同一步的 `TO − IC`，左右差取右减左；缺 TO 的步仍计步，但不参与接地统计。
- **报告俯仰**取同脚 IC / TO 原始事件帧的 App 导出 `pitchDeg`，单位为度，不使用邻帧或估计值补空。分段均值按脚统计有效设备俯仰；它不是足部对地角。
- **逐步表**默认显示设备俯仰，可单独查看设备侧倾 `sideTiltDeg` 或足部俯仰估计。无设备角的旧包仍可看足部俯仰估计，但不计入设备俯仰汇总。
- **三轴加速度合量峰值**：在同脚 `[IC, IC+100 ms)` 内取 `hypot(ax, ay, az)` 的最大原始采样及其录制时刻；并列取首个。单位为 g，包含重力，不是垂向加速度或地面反作用力。断流、窗口不完整或疑似削顶时峰值和峰时均留空。
